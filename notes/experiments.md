# M6 ANE 实验总览

- 日期：2026-10-03
- 机器：M6（T8152，h18g），16 GB，macOS 27.0.1（26A434），ANE 编译器 `zin_ane_compiler v10.26.6`。
- 本文把 `repro_plan.md` 的 A–G 组（34 项，对应 maderix Part 1–4 与 Bryngelson 论文）和 H 组（44 项计划外补充）按主题重新归类，只列结论和出处；细节、原始数据见各分册。
- 分册：`compute_array.md`（计算阵列）、`memory.md`（存储与带宽）、`scheduling.md`（调度与开销）、`bonded_measure.md`（双 ANE）、`power.md`（电源与频率）、`numerics.md`（数值）、`hwx_h18g.md`（编译产物格式）、`compile_cost.md`（编译耗时）、`hal_analysis.md`（HAL 参数表）、`defects.md`（疑似缺陷）、`comparison.md`（与 M1 / M4 / M5 对照）。

## 1. 测量手段

| 手段 | 测什么 | 要 root | 工具 |
|---|---|---|---|
| 改层数取斜率 | 每层的 ANE 执行时间（扣掉每次调用的固定开销） | 否 | `tools/common/chain.py`（生成卷积链）、`bondrun.m`、`runall.sh` |
| IOReport | 每个 ANE 的中断数（判断用了哪个 ANE、是否退回 CPU）、DRAM 链路带宽、时钟开启时间、降频事件 | 否 | `bondrun.m`、`anewho.c`、`iorlist.c` |
| kdebug 固件事件（子类 0x061b） | ANE 任务起止（`61b0125` / `0126`，cpu 列 36 = ANE0、33 = ANE1）、提交、固件消息、中断、驱动完成、用户返回；单 ANE 时没有任务开始事件 | 是 | `*_ktrace.sh` 系列 + 对应的 `.py` 分析脚本 |
| SMC 功率 | ANE 电源轨 `PP0b`、整机 `PSTR` | 否 | `smcpower.c` |
| 设备树 | ANE 频率表、内存通道与 die、电源域 | 否 | `ioreg -p IODeviceTree` |
| 编译器只读调用 | HAL 参数表、SoC 频率 / 内存参数、直接编译出 HWX | 否 | `dump2.c`、`socfreq.c`、`anecc.m` |
| 编译器静态逆向 | 函数机器码、调用关系、地址引用、跳转表、查表 | 否 | `fnbytes.c`、`xref.c`、`adrref.c`、`jtab.c`、`tblread.c`、`immscan.c` |
| HWX 解析 | TD 指令流、包头、寄存器地址 → 值、卷积配置字 | 否 | `tdpkt.py`、`td_widths.py`、`convcfg.py`、`ks4_td.py` |
| GPU 带宽 | DRAM 总带宽对照 | 否 | `membw.swift` |

约定：每个实验都检查中断，确认在 ANE 上执行（Core ML 会悄悄把小模型、部分算子放到 CPU）；先预热 ≥ 1 s；每点至少两轮。

## 2. 结论（按主题）

### 2.1 硬件结构与频率

| 项目 | 结论 | 出处 |
|---|---|---|
| 规模 | 2 个 ANE × 16 个 NE；每 NE 每周期 256 次 FP16 乘加 | power.md §6.0、H30 |
| 频率 | 满载 **2.58 GHz**（设备树最高档，由固件任务时长在升频台阶上反推，低档拟合 RMS 0.2%）；编译器表最高只到 2.508 GHz | power.md §6.5、H34 |
| 峰值 | 直接卷积单 ANE 21.1 TFLOPS，双 ANE 42.3 | B1 |
| 时钟机制 | 每个 ANE 两个 PLL，无独立调压域，经 SOC Floor 请求电压；从空闲升到满速约 0.3 s（期间慢 2.8 倍） | power.md §2、§6.4 |
| 内存 | 1 个内存控制器 × 8 个 DRAM 通道（全部启用），每通道一颗美光 die（16 GB，单 rank），有 ECC；**不是三通道** | memory.md C2k、H43 |
| TD 布局版本 | **M6（h18g）= v24**（h19 也是 v24，h18 是 v20）；由编译器 `ZinCpuSubtypeToArchValue` 查表确定，v26–v36 属于更新的架构 | hwx_h18g.md §11.3、H41 |

### 2.2 计算阵列

| 项目 | 结论 | 出处 |
|---|---|---|
| FP16 吞吐 | 单 ANE 20.6 TFLOPS（理论 97.5%），双 ANE 39.5（1.92×） | bonded_measure.md、B1 |
| 输出通道台阶 | 只有 256 → 272 一个明显台阶（+32%）；Cout ≥ 16 时 16 个 NE 全部启用 | compute_array.md B2、B3 |
| Winograd | **硬件实现**，按形状启用：3×3 单 ANE 有效 31 TFLOPS（超过直接峰值）；1×3 走一维 Winograd；膨胀卷积不用 | compute_array.md B5、H10 |
| W8A8 | 每个累加器在 int8 时同时算 2 个输出通道（编译器性能模型与 HAL 参数），等价每 NE 512 次 int8 乘加 / 周期（单引擎 1×1 实测 428，超过 FP16 上限 256）；3×3 上实测正是 FP16 的 2.0 倍（单 ANE 有效 62 TOPS）；1×1 链受激活带宽限制，双 ANE 时与 FP16 持平；int8 权重 + fp16 激活基本不加速 | H10、H51、B6、B7 |
| space_to_depth | 9.5 → 31.7 TFLOPS（3.3×），M6 没有 block = 2 陷阱 | B8 |
| 卷积核形状 | 原生核（核宽 ≤ 8，竖向到 15×1）单 ANE 90–96%；核宽 9–15 被改写为步长 2（Kw = 核宽 + 1 再补偶数，权重约翻倍），耗时 = 权重量 ÷ 约 150 GB/s；核宽 ≥ 16 编译失败、整个模型退回 CPU | compute_array.md B4c、H38、H39 |
| 每 NE 权重缓冲 | 64 KiB（三条间接证据：每层 TD 数、HAL"常驻权重上限" = 64 KiB、共享权重时 DRAM 读取量在 64 KiB 处分界）；超过时切成多趟或边算边读，受读权重带宽限制 | compute_array.md B4c 第 7 点 |
| 窄宽度 | 宽度 ≤ 约 32 时按行计时，窄了就浪费 | B4c 第 3 点 |

### 2.3 存储与带宽

| 项目 | 结论 | 出处 |
|---|---|---|
| 片上中间张量 | 每块必须 < 2 MiB，块数 = ⌊大小 / 2 MiB⌋ + 1；有层融合，计时看不到拐点 | memory.md C1、C1b |
| L2 大小 | **每个 ANE 2 MiB**：编译选项 `L2Size` 默认正好 2048 kB（≥ 2048 与默认逐字相同，2047 就不同，更大也不变），默认编译时缓冲放到 [1.5 MiB, 2 MiB)；TD 地址字段上限也是 2 MiB。物理 SRAM 无直接读数 | memory.md C1d |
| 权重工作集 | 8 MB 已放不进片上；权重超出时每层重读 | C2、C2d |
| 读权重带宽 | **约 150 GB/s**，与每层大小、核形状无关；两个 ANE 共享，合计约 140–150 | C2b–C2j、C3 |
| DRAM 总带宽 | ANE 单独 153、GPU 单独 143–146、两者同时合计约 160–168 GB/s（理论约 170） | C2k、H43 |
| 激活带宽（Tile DMA） | 每个 TD 最多读 2 个、写 1 个 DRAM 张量；两路输入共用带宽，每个 ANE 读写合计约 35–40 GB/s（kdebug 任务时长），两个 ANE 约 70–80 GB/s；同一张量用两次会读两次。原 C3 / C4 的"逐元素约 40 GB/s""每多一个输入 +52 µs"按调用总耗时算，含主机开销，已更正 | C3b（更正 C3、C4） |

### 2.4 调度与每次调用的开销

| 项目 | 结论 | 出处 |
|---|---|---|
| 每次调用开销 | 提交侧约 30 µs + 任务结束后 130–325 µs（随任务时长变化，超过约 350 µs 后饱和在约 320 µs，**不按层数增长**）；2–3 次中断 | scheduling.md D1、D1c、H42 |
| 主机唤醒 | 任务结束后的增长全在驱动完成处理和用户线程唤醒两段，原因是等待期间 CPU 进入更深空闲；让 CPU 保持忙碌即可消除 | memory.md C2j、H33 |
| 每层固定开销 | ≤ 13 ns（按 2.58 GHz ≤ 约 34 个周期） | D6b |
| 并行 / co-issue | 独立支路串行；MAC 与 PE、DMA 与 PE 等都不重叠；层内有流水线 | D3、D4 |
| 并发 | 同一程序在一个进程里严格串行（多线程无加速，只用 ANE0）；不同程序或不同进程可分到两个 ANE（约 1.8×） | D2、H15 |
| 图深度上限 | 386 层：双 ANE 编译路径的递归调度栈溢出；之后悄悄退回 CPU 或加载卡死 | D5、H9 |
| 执行计划 | 部分深度（32、34 层）下 Core ML 把最后一个 relu 放到 CPU，多约 100 µs | compute_array.md B6b、H36 |

### 2.5 双 ANE（bonded）

| 项目 | 结论 | 出处 |
|---|---|---|
| 何时切到双 ANE | 公式：切 ⇔ Σ切分前延迟 > ½（Σ切分后各块 + Σ拷贝 / 合并），× 0.5 即假设两 ANE 完全并行、不争带宽（B9 的根因）；按行切的拷贝开销只在切后每块 ≤ 128 像素时出现，约与张量字节数成正比（256 通道约 45）。编译期由空间切分的成本模型决定（比较候选切法的估计延迟）。两种切法：**按行**（整条链融合切块，竖向核带 halo）和**按输出通道**（把单 ANE 时的权重分趟平均分给两个 ANE，只在各趟大小相同时）。8×32 按行切的门槛约为编译器估计延迟和 45；4×32 从不切；读权重流式（1×9–1×15）、两趟不均（3×3、9×1、11×1）的层在 8×32 不切 | bonded_measure.md §2.1、H48 |
| 权重 | 两个 ANE 各读一份权重；读权重受限时收益从 1.9× 降到约 1.4× | H4 |
| 切块不均 | 沿用不分引擎时的切块网格，块数为奇数时多出的一块给 ANE1，慢 12.5–19%；块数为偶数时均衡 | memory.md C1c、H37 |
| 按行切分的浪费 | 读权重受限的层若按行切分，两个 ANE 各读完整权重，没有加速（16×32 的 1×9 等） | B4c 第 8 点、defects.md B9 |
| 同步 | 跨 ANE 屏障 `f0003281`，个数等于数据交换次数；共享区经 SLC | hwx_h18g.md §6–7 |

### 2.6 电源

| 项目 | 结论 | 出处 |
|---|---|---|
| 空闲 | ANE 电源轨 0 W；最后一次推理后 5.68 s IOP 断电，10.2 s 维护计时器重新上电并撤下程序，约 15.3 s 再断电 | power.md §1、§3.1、H16 |
| 冷唤醒 | < 5.7 s 约 6.8 ms；断电后约 50 ms | §3、§3.1 |
| 功率 | 单 ANE FP16 6.5 W，双 ANE 11.3 W（2.7 TFLOPS/W）；W8A8 3.4 TOPS/W；读权重受限时仅 2.5 W | §5 |
| 降频 | 5 分钟满载不降频 | §4 |

### 2.7 数值

| 项目 | 结论 | 出处 |
|---|---|---|
| 累加器 | 32 位定点（Q15.16），绝对值 ≥ 32768 变成 inf 并"粘住"；bias 是累加器初值 | numerics.md、H11 |
| 小乘积 | x、w 指数和 ≤ −17 时整个丢掉 | H12 |
| int8 累加器 | **32 位有符号整数**：整数和 2^30 准确、2^31 溢出成 inf（与输出值大小无关）；没有 fp16 路径的 ±32768 上限，缩放在累加之后 | numerics.md H50 |
| 舍入 / 特殊值 | 输出远离零舍入；NaN 当作普通大数解码；PE 走浮点路径 | F2 |
| 激活函数 | 33 点查找表（[−8, 8]，间距 0.5，按对称和区间归约）；gelu 两种模式逐位相同；sqrt / rsqrt ≤ 1.5 ulp | F3、F3b、H13 |

### 2.8 编译器与编译产物

| 项目 | 结论 | 出处 |
|---|---|---|
| HWX 格式 | h18g 新格式，每个模型有 nonbonded / bonded 两套程序；50 种层、33 种激活 | hwx_h18g.md §1–8 |
| 指令流打包 | 包头低 15 位 = 寄存器字地址；bit 31 = 0 连续写，= 1 按 16 位掩码写；"未知字 X"就是掩码包头；bit 29 = 1 的是地址包，bits 21–28 为 BAR 编号（4 权重、20 DSID、24 起先输出后输入、每个张量 4 个槽）；TD 头依次为 tid + 长度、exe_cycles（编译器估计执行时间）、log / debug log / DRAM log 事件掩码、标志字 | hwx_h18g.md §11.1、§11.4、H40、H46 |
| 寄存器布局 | 19 个编译目标按布局分 4 组；h18g 与 h19 相同；变化发生在 v8 → v17（DMA）、v19 → v20（L2）、v20 → v24（NE） | §11.2 |
| 卷积配置字 | Kw 0–5、Kh 6–11、Sx 13–14、Sy 15–16、PadLeft 17–21、PadTop 22–26、Ox 28–29、Oy 30–31；Ox = 每个输入步长产生的输出像素数 | §10 |
| SoC 参数 | 编译器为每个目标内置 NE / DRAM / DMA 频率表、通道数、MCache；M6 用 `Soc2026BaseLine`（每块 0xa0 字节，H17s 的"第二组表"是读越界读到 H18） | power.md §6.1–6.2、H27–H29、H44 |
| 编译耗时 | 双 ANE 版本对逐元素层超线性（约 3.5–3.8 次方，512 层 179 s）；经 Core ML 首次加载时编译只在 E 核上跑，慢 2.7 倍 | compile_cost.md、H7、H35 |

## 3. 被推翻或更正过的结论

报告中只写更正后的版本，但这些过程本身说明了测量方法上的坑。

| 原结论 | 更正 | 怎么发现的 |
|---|---|---|
| 读权重有两种带宽（≤ 48 MiB 约 130、≥ 50 MiB 约 150 GB/s） | ANE 一直约 152 GB/s；台阶在主机侧（CPU 深度空闲导致唤醒变慢） | 固件任务时间戳 + 阶段拆分 + 空转对照（H33） |
| 任务以外每层约 0.48 µs | 不存在；是 16 / 384 层两点连线跨过 CPU 空闲台阶的假象 | 层数相差 4 倍、任务时长相同的两组模型（H42） |
| ANE 频率 2.508 GHz（编译器表） | 实际 2.58 GHz | 固件任务时长在升频台阶上反推（H34） |
| FP16 32 层"反常地慢"与权重有关 | 两个效应：主机唤醒，加上 Core ML 把 relu 放到 CPU | 执行计划 + 阶段拆分（H36） |
| bonded 时 ANE1 每层固定多 10.6 µs / 与对齐有关 | 切块网格分组，奇数块给 ANE1 | 编译产物块宽统计 + 预测验证（H37） |
| 1×16 的"效率悬崖" | 编译失败，整个模型退回 CPU | 中断计数为 0 + `ANECCompile` 返回值（H38） |
| 1×9 等长条形核效率 18–60% | 单 ANE 下 85%，受读权重带宽限制；之前混入了窄宽度和单 / 双 ANE 切换 | 不切换的形状 + 固件时间戳重测（H39） |
| 改写时"核宽补成偶数" | Kw = 核宽 + 1 再补偶数（1×10 → 12、1×12 → 14） | 编译产物配置字（H39） |
| `0x93498005` 是一个配置字 | 是按掩码写的包头 | 解出包头格式（H40） |
| M6 = v31、H19 = v36 | M6 和 H19 都是 v24 | 逆向编译器分发代码（H41） |
| H17s 有第二组频率表 | 读越界读到相邻的 H18 块 | 数据块地址间距（H44） |

## 4. 疑似缺陷

见 `defects.md`：A 类疑似 bug 2 条（h18g 编译栈溢出；编译服务崩溃后加载卡死或静默退回 CPU），B 类性能问题 10 条（含双 ANE 编译超线性、编译只在 E 核、同程序串行、W8A8 激活走 DRAM、主机唤醒、频率表偏低、relu 放到 CPU、切块不均、按行切分浪费、PE 时钟升频慢且 GPU 并发时被压回慢档），C 类未写进文档的行为 9 条。

## 5. 局限与未验证

- 只有一台 16 GB 的 M6；"32 GB 版本单个引擎可达 170 GB/s"未验证。
- 不执行修改过的 HWX（不绕过 Core ML / aned），所以寄存器含义只能靠编译比对和计时推断。
- 实际 DRAM 频率读不到（设备树频率字段被隐藏）；ANE 频率由时间戳反推，不是直接读数。
- 未逐位解码的部分：事件掩码（log / debug log / DRAM log）各位的含义；L2 块寄存器在 v24 中的硬件地址。（卷积配置字 bit 12、27 已确认为保留位；TD 末尾的 `0x2xxxxxxx` 字已查明是地址包，见 hwx_h18g.md §11.4。）
- L2：编译器按 2 MiB 使用且用满，但芯片上的物理 SRAM 大小没有直接读数。
- 双 ANE 成本模型：公式已逆向；"拷贝 / 合并"开销只在切后每块 ≤ 128 像素时出现，对应的代码位置未定位。
- Bryngelson 书中"M5 = v20"与本机编译器表（H17 = v19、H18 = v20）不一致，未核实原因。
