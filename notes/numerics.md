# ANE 数值行为（M6 h18g，并在 M4 h16g 上复测）

- 日期：2026-10-02
- 工具：`tools/06_numerics/numerics.py`、`numerics2.py`、`numerics3.py`、`numerics4.py`、`numerics5.py`、`numerics6.py`
- 原始输出：`data/06_numerics/numerics2_m6.txt`、`data/06_numerics/numerics2_m4.txt`、`data/06_numerics/numerics3_m6.txt`、`data/06_numerics/numerics4_m6.txt`

## 方法

- 每个用例是一个 1×1 卷积：x 为 [1, 64, 1, 256]，每一列是一个独立用例，第 0 个输出通道的权重是要测的图样，输出 = Σ x·w。
- Core ML 会把单个小卷积放到 CPU 上。所以输出通道补零到 2048，并在后面接一条"陪跑"支路（4 层 conv+relu），让整个模型被放到 ANE 上；测试卷积的原始输出单独作为一个模型输出读出。
- 确认真的在 ANE 上跑，用了两种办法：
  - `anewho` 看到 ANE 中断；
  - 同一个模型用 CPU_ONLY 再跑一遍，结果不同。
- 逐元素运算（add / mul / sub）用同样方法测。

## 结论：MAC 路径（卷积 / 矩阵乘）

| 项目 | M6 和 M4 的实测（两者完全相同） | 论文的说法 |
|---|---|---|
| 累加器 | **32 位定点：16 位小数，绝对值范围 < 2¹⁵**（LSB = 2⁻¹⁶） | fp32 级的宽累加器 |
| 溢出 | 累加过程中任何时刻绝对值 ≥ 32768 → ±inf，而且粘住（之后再减回来也还是 inf） | M1/A14 在 32768 饱和，M5 不饱和 |
| 小于 LSB 的乘积 | **按指数判断**：x 与 w 的指数之和（非规格化数按 −14）≥ −16 时，乘积四舍五入（远离零）到 2⁻¹⁶；≤ −17 时整个乘积丢掉，即使实际值有 1.98 LSB（见 H12） | 非规格化数：M1 清零，M5 保留 |
| 归约顺序 | ±2048 中间加 +1，无论位置都不会被吞，说明没有 fp16 的部分和 | M1 是 radix-4 的 fp16 部分和 |
| 输出舍入（定点 → fp16） | **四舍五入，远离零**：2049 → 2050，−2049 → −2050，4098 → 4100，1+2⁻¹¹ → 1+2⁻¹⁰ | round-half-to-even |
| 输入解码 | fp16 指数域为 31 的值当普通数解码：inf → 2¹⁶，NaN 0x7E00 → 1.5·2¹⁶，0x7FFF → 131008。所以"NaN 变 +inf"的原因是：解码后的大数让累加器溢出 | NaN 变成 +inf |
| 输入范围 | 65504 × 2⁻⁴ = 4094 正确，说明输入不会先溢出，只有累加器溢出 | — |
| 刻度是否随权重变化 | 权重为 1、16、256、4096 时，溢出点都是 32768，LSB 都是 2⁻¹⁶。是固定刻度，编译器不按层调整 | — |
| −0 | 输出 +0 | — |

具体数据：

| 用例 | ANE | CPU |
|---|---|---|
| 32752（单个输入，权重 1） | 32752 | 32752 |
| 32768 | **inf** | 32768 |
| 16384 + 16376（= 32760，舍入成 32768） | 32768 | 32768 |
| 16384 + 16384 | **inf** | 32768 |
| 16384 + 16384 − 16384 − 16384 + 1 | **inf** | 1 |
| 16384 + 2⁻¹⁶ − 16384 | **2⁻¹⁶** | 0 |
| 16384 + 2⁻¹⁸ − 16384 | 0 | 0 |
| 2⁻¹⁷（权重 1） | 2⁻¹⁶ | 2⁻¹⁷ |
| 2⁻¹⁸（权重 1） | 0 | 2⁻¹⁸ |
| 2048 + 1 | **2050** | 2048 |
| −4096 − 2 | **−4100** | −4096 |

### 含义

1. **累加器是定点数，不是浮点数。** 这解释了论文观察到的"在 32768 饱和"：32768 = 2¹⁵ 正是定点整数部分的上限。M6 上的表现是溢出变成 inf，而不是饱和。
2. **对网络的影响**：
   - 任何卷积 / 矩阵乘的中间累加值不能超过 ±32768。
   - 小于 2⁻¹⁷ 的乘积会被丢掉，所以非常小的激活乘非常小的权重会精度不足。
   - 这就是为什么 ANE 上大模型常需要先缩放激活（例如 LLM 的 RMSNorm 前后）。
3. M4（h16g）和 M6（h18g）完全一致，说明这个设计至少从 H16 起没变。M1 上是否不同，有待有 M1 的人复测。论文说 M1 在 32768 饱和、M5 不饱和，和我们的测法不同，不能直接比较。

## 结论：PE 路径（逐元素运算）

| 用例 | ANE | CPU | 说明 |
|---|---|---|---|
| add 2048 + 1 | 2050 | 2048 | 舍入方式同 MAC 路径：远离零 |
| add 65504 + 0 | 65504 | 65504 | **没有 32768 的限制** |
| add 40000 + 1 | 40000 | 40000 | |
| add 16384 + 16384 | 32768 | 32768 | |
| add 2⁻²⁴ + 0 | 2⁻²⁴ | 2⁻²⁴ | 保留非规格化数 |
| mul 2⁻¹² × 2⁻¹² | 2⁻²⁴ | 2⁻²⁴ | |
| mul 256 × 256 | inf | inf | 超过 fp16 范围才溢出 |
| NaN + 1 | **inf** | NaN | 输入解码方式同上 |

- 逐元素运算走的是浮点路径，范围是 fp16 的范围，和 MAC 的定点累加器不是同一套硬件。
- 结构上，这和论文"NE（MAC）+ PE（平面引擎）"的分工一致。

## F3：激活函数（查表 + 线性插值）的误差

- 工具：`tools/06_numerics/lut_err.py`（采集）、`tools/06_numerics/lut_plot.py`（画图）。
- 图：`figs/zh/light/fig8-2_lut_error.png`（12 个函数全貌）、`figs/zh/light/fig8-3_lut_error_zoom.png`（sigmoid / gelu / silu / tanh 近景）。
- 原始数据：`data/06_numerics/lut_m6/*.npz`、`data/06_numerics/f3_lut_m6.txt`。
- 方法：输入是 [−R, R] 上 52 万个点的 fp16 网格（正值函数用对数网格）。ANE 输出减去 float64 精确值得到误差。陪跑支路保证在 ANE 上执行（两个 ANE 都有中断）。

| 函数 | ANE 最大绝对误差 | CPU 最大绝对误差 | 说明 |
|---|---|---|---|
| sigmoid | 3.4e-3 | 7.0e-4 | **[−8, 8] 上每 0.5 一个采样点，共 33 点**（采样点上的误差只有中点的 4–11%）；超出 ±8 饱和 |
| tanh | 1.6e-3 | 9.6e-4 | 在 ±4 处有不连续；采样间距的最佳拟合是 0.125（±2 内 33 点），还需确认 |
| gelu（EXACT） | 6.2e-3 | 1.7e-3 | 最佳拟合间距 0.46，不是整数倍网格 |
| gelu（TANH 近似） | 6.2e-3 | 3.9e-3 | **ANE 输出和 EXACT 模式逐位相同（100%）**，CPU 上两者有 78% 的点不同 |
| silu | 1.5e-2 | 4.8e-3 | 不等于 x × ANE 的 sigmoid（只有 38% 的点相同），是单独的实现 |
| exp | 相对误差 ≤ 9.1 ulp | | |
| log | 6.6e-3（≤ 91 ulp） | | |
| sqrt | ≤ 1.2 ulp | | 精度很高，可能是专用硬件（maderix：rsqrt / sqrt / reciprocal 有专用硬件） |
| rsqrt | ≤ 2.1 ulp | | 同上 |
| inverse | ≤ 13.5 ulp | | |
| erf | 8.6e-4 | 9.8e-4 | |
| sin | 6.3e-4 | 2.4e-4 | |

- 2026-10-05 更正：ulp 原按 |误差| ÷ (max(|精确值|, 2⁻¹⁴) × 2⁻¹⁰) 计算，这是随数值连续变化的近似；现改按 FP16 的实际间距（精确值所在指数区间内相邻可表示数的距离，同 numpy.spacing），各函数的最大 ulp 最多增大约 2 倍（`tools/06_numerics/lut_ulp.py`，`data/06_numerics/lut_ulp_m6.txt`）。

结论：
1. **sigmoid 是 33 点均匀查表加线性插值**（[−8, 8]，间距 0.5），和 maderix 在 M4 上的"33 个 fp16 采样点"一致。
2. **gelu 不论选 EXACT 还是 TANH 近似，在 ANE 上都是同一张表**，选哪种模式不影响结果。
3. sqrt / rsqrt 误差在 1.2–2.1 ulp 以内，不像查表，支持"有专用硬件"的说法。
4. silu、erf、sin、gelu 的采样点不在以 0 为原点的整数倍网格上，可能有偏移或者不均匀。还要做两参数（起点、间距）搜索，或者对照编译产物 `__KERN_0` 里的表。

## F3b：从编译产物直接读出查找表（A6）

- 方法：每个激活函数编一个"1×1 卷积 + 激活"的小模型（`tools/06_numerics/opvariants.py`，h18g，只编译），读 `__KERN_0` 段里非权重的数据。sigmoid 等的表在段首偏移 0x8；sqrt / rsqrt / inverse / log / floor 的表有单独的符号 `K<哈希>_actlut`，在 0x2000 或 0x2800。
- 原始数据：`data/06_numerics/opv_hwx/act_*/model.hwx`。

| 函数 | 表的内容（33 个 fp16） | 实现方式 |
|---|---|---|
| relu、abs、sign、square | 无表 | ALU 直接计算 |
| sigmoid | σ(−8), σ(−7.5), …, σ(8) | [−8, 8] 等距 33 点，存精确采样值 |
| tanh | tanh(0), tanh(0.125), …, tanh(4) | **只存正半轴** [0, 4]，间距 0.125，利用奇对称；所以 ±4 处不连续 |
| erf | erf(0), erf(1/16), …, erf(2) | 只存正半轴 [0, 2]，奇对称 |
| sin | sin(0), sin(π/64), …, sin(π/2) | **只存四分之一周期**，其余靠对称 |
| exp | 1.0, 1.0215, …, 2.0（即 2^(i/32)） | **换算成 2 的幂**：整数部分写进浮点指数，表只覆盖 2^f，f ∈ [0, 1] |
| log | 表头 0, inf, −inf, 0，后面是 log2(0.5)…log2(0.9375)，间距 1/64 | 区间归约：log2(尾数) + 指数，再乘 ln2 |
| sqrt | 表头 0, inf, 0, inf…，后面是 sqrt(0.5)…sqrt(1.75)，间距 1/16 | 区间归约（按指数奇偶拆分） |
| rsqrt | 同上网格：1.414 … 0.756 | 区间归约 |
| inverse | 表头 0, inf, inf, 0，后面是 1/0.5 … 1/0.9375，间距 1/64 | 区间归约 |
| floor | 表头 −inf, inf，其余为 0 | 不是普通查表，机制不同 |
| gelu | [−4, 4]，间距 0.25；**值是拟合的**：gelu(0.25) 应为 0.1497，表里是 0.1436 | 为整体误差最小而拟合，所以误差零点不在采样点上 |
| silu | [−8, 8]，间距 0.5；同样是拟合值（silu(0.5) 应为 0.311，表里 0.296） | 同上 |

结论：
1. 所有查表函数都是 **33 点线性插值**，但不是同一张网格：编译器会**利用对称性**（tanh、erf、sin 只存一部分）和**区间归约**（exp、log、sqrt、rsqrt、inverse 只覆盖一个倍频程，指数单独处理），让 33 个点覆盖尽量多的精度。sqrt / rsqrt 误差 ≤1.5 ulp 是区间归约的结果，不一定需要专用硬件。
2. gelu、silu 的表值是**拟合值**，不是采样值，这解释了 F3 中误差零点不在等距网格上、最佳拟合间距"奇怪"的现象。
3. 和 maderix（M4）的"33 个 fp16 采样点存在 `__KERN_0` 里"一致；M6 上可以看出更多细节：对称、区间归约、表头特殊值。

## H11：bias 在哪里加（2026-10-02）

- 工具：`tools/06_numerics/numerics5.py`（第一部分）。权重全为 1，第 0 个输出通道 = Σx + bias。原始数据：`data/06_numerics/numerics5_m6.txt`。

| bias | 输入 | ANE | CPU | 说明 |
|---|---|---|---|---|
| −16384 | 16384 + 16384 | **16384** | 16384 | 没有溢出：bias 在累加过程开始时就在累加器里 |
| −16384 | 16384 × 3 | inf | 32768 | 最终值达到 32768 照样溢出 |
| +32 | 32752 | **inf** | 32768 | bias 和乘积一起受 ±32768 限制 |
| +32 | 32736 | **inf** | 32768 | 32768 本身就溢出 |
| 2⁻²⁰ | 0 | **0** | 9.5e-7 | bias 先被量化到 2⁻¹⁶ |
| 2⁻¹⁷ | 0 | **2⁻¹⁶** | 2⁻¹⁷ | 0.5 LSB 远离零舍入 |
| 2⁻¹⁷ | 2⁻¹⁷（权重 1） | 2⁻¹⁵ | 1.5·2⁻¹⁶ | 两者各自舍入成 1 LSB 后再相加 |
| 1000.5 | 0.25 | 1001 | 1001 | 输出舍入到 fp16，同 CPU |

结论：**bias 是定点累加器的初值**（Q15.16，先远离零舍入到 2⁻¹⁶），不是在输出端用浮点加的。所以 bias 也计入 ±32768 的范围，大 bias 加大激活会溢出；反过来，一个负的大 bias 能"抵消"一部分正的乘积，让中间值不溢出。

## H12：小于 1 LSB 的乘积何时被丢掉（2026-10-02）

- 工具：`tools/06_numerics/numerics5.py`（第二部分：乘积为 0.25–3.5 LSB，权重 2⁻¹²–2⁴ 及 0.75、1.5、3、0.375），`tools/06_numerics/numerics6.py`（区分实验）。原始数据：`data/06_numerics/numerics5_m6.txt`、`data/06_numerics/numerics6_m6.txt`。
- 第二部分的现象：
  - 权重 ≤ 2⁻³（x 是规格化数）时，0.25、0.5、0.75 LSB 都变成 0，1.5 → 2、2.5 → 3、3.5 → 4。
  - 权重 ≥ 2⁻²（x 是非规格化数）时，0.5、0.75 LSB → 1，0.25 → 0。
  - 不是 2 的幂的权重：2.499 → 2、2.501 → 3、3.498 → 3，舍入本身是正常的四舍五入（远离零）。
- 两种解释：按"乘积 < 1 LSB"判断，还是按"x 指数 + w 指数"判断。区分实验专门构造了"指数和为 −17、但尾数乘积 ≥ 2"的用例：

| w | x | 指数和 | 乘积实际值 | ANE |
|---|---|---|---|---|
| 1.875·2⁻³ | 1.875·2⁻¹⁴ | −17 | 1.76 LSB | **0** |
| 1.99·2⁻³ | 1.99·2⁻¹⁴ | −17 | 1.98 LSB | **0** |
| 1.5·2⁻⁴ | 1.9·2⁻¹³ | −17 | 1.43 LSB | **0** |
| 1.9375·2⁻⁵ | 1.9375·2⁻¹² | −17 | 1.88 LSB | **0** |
| 0.2 | 0.99·2⁻¹⁴（非规格化） | −17 | 0.79 LSB | **0** |
| 0.125 | 1.5·2⁻¹³ | −16 | 1.5 LSB | 2 |
| 0.25 | 0.5·2⁻¹⁴（非规格化） | −16 | 0.5 LSB | 1 |

结论：
1. **规则是按指数判断**：x 和 w 的指数之和（非规格化数按 −14 计）≥ −16 时，乘积按四舍五入（远离零）对齐到 2⁻¹⁶；≤ −17 时整个乘积丢掉，即使实际值接近 2 LSB。
2. 推测乘法器输出"尾数积（[1, 4)）+ 指数和"，对齐移位器只为指数和 ≥ −16 的乘积保留舍入位，更小的直接移出。
3. 之前"权重 < 1 时 0.5 LSB 被丢掉"只是这条规则的特例：0.5 LSB 的乘积在 x 为规格化数时指数和必为 −17 或更小，在 x 为非规格化数（指数按 −14 计）且 w ≥ 2⁻² 时指数和 ≥ −16。
4. 对网络的含义：非常小的激活乘以小权重会被截掉，而且最多可以截掉近 2 LSB（约 3·10⁻⁵），比"小于半个 LSB 才丢"更粗。

## H50：int8（W8A8）路径的累加器位宽（2026-10-03）

- 工具：`tools/06_numerics/numerics_i8.py`（`./anewho python numerics_i8.py <目录>`，环境变量 `I8_ROUND` 选轮次、`I8_K` 选缩放）。数据：`data/06_numerics/numerics_i8/`。
- 方法：不用校准，手写 `quantize → dequantize → conv(constexpr_blockwise_shift_scale(int8 权重))`，缩放完全可控。输入、权重量化后全为同一个 int8 值（127 或 −128），所以每个输出点的整数累加和 S 精确已知；缩放 sx = sw = 2^-k，输出理论值 = S·2^-2k。每个模型同时跑 ANE 和 CPU_ONLY；ANE 与 CPU 结果相同的点视为被放到了 CPU 上（小模型、输入通道 ≥ 120000、过大的 9×1 输入），不计。

| 轮次 | 卷积 | S | 缩放 | 理论输出 | ANE |
|---|---|---|---|---|---|
| 1 | 1×1，N = 2048–16384，127 × 127 | 2^25 – 2^28 | 2^-14 | 2016 – 16129 | 与理论一致（fp16 输出精度内） |
| 1 | 1×1，N = 4096–16384，127 × 127 | 2^26 – 2^28 | 2^-12 | 16129 – **64516** | 16128 – **64512**，**没有 fp16 路径的 ±32768 上限** |
| 1 | 1×1，一半通道权重为 −127（和为 0，部分和到 2^27） | — | — | 0 | 0 |
| 2 | 1×1，N = 65536，127 × 127 | 2^30 | 2^-16 | 16129 | 16128 |
| 3 | 1×1，N = 65536，(−128) × (−128) | **2^30** | 2^-16 / 2^-18 | 16384 / 4096 | **准确** |
| 3 | 2×1，N = 65536 | **2^31** | 2^-16 / 2^-18 | 32768 / 8192 | **inf** |
| 3 | 3×1，N = 65536；8×1、9×1，N = 16384 | 1.5·2^31、2^31、1.125·2^31 | 同上 | — | **inf** |
| 3 | 3×1，正负交替（部分和 ≤ 约 2^30，最终 1.008·2^30） | — | 同上 | 16512 / 4128 | 准确 |

- 样本取舍（2026-10-05 补）：上表只取 ANE 输出与 CPU_ONLY 不同的模型（结果不可能来自 CPU）。ANE 与 CPU 输出相同不能当作"落到 CPU"的判据：N = 2080 两边都输出 2048（理论 2047.6 的正确舍入），多半就是 ANE 算的。N ≥ 120000 不能上 ANE 是因为单维度超过 65536（报告表 5-22），N ≤ 1024 推测按分段代价放到 CPU，未逐个核对。
- 结论：
  1. **int8 路径的累加器是 32 位有符号整数**：S = 2^30 准确，S = 2^31（int32 最大值 + 1）即溢出；溢出与输出值大小无关（缩放改为 2^-18 时，S = 2^31 对应的输出只有 8192，仍然溢出）。
  2. **溢出变成 inf**，与 fp16 路径一样不饱和。
  3. 累加在整数域完成，缩放在最后：输出可以超过 32768（到 64512），说明 int8 路径不经过 fp16 路径的 Q15.16 定点累加器（那个累加器在 32768 处溢出）。
  4. 实际意义：int8 × int8 的单个乘积最大 2^14，一个输出点要累加约 13 万个最大乘积才会溢出；常见网络（输入通道 × 核面积 ≤ 几万）不会碰到。
