# Apple M6 神经网络引擎的微体系结构

[English](README.md) | 中文

本仓库是技术报告《Apple M6 神经网络引擎的微体系结构：基于编译产物、执行追踪与功耗测量的实证研究》的配套仓库，存放报告正文以及支撑报告结论的原始数据、实验工具、分析脚本和图。

报告研究 Apple M6（T8152，ANE 编译目标 h18g）的神经网络引擎（ANE），涵盖程序格式与编译器、调度、计算阵列、数值行为、存储层次、双引擎协同、时钟、调频和功耗，并以 M4 为对照。全部实验只通过公开接口执行模型，对编译器、驱动和固件只做只读分析。

报告以中文写成，英文版由中文版翻译而来；两者不一致时以中文版为准。

## 仓库的定位

- **报告是结论的唯一出处。** 报告中的每条结论都带有证据类别标注，并直接链接到对应的数据文件和工具，读者可以从报告出发核对任何一个数字。
- **`data/` 和 `tools/` 是报告的证据。** 原始数据保持实验时的原样；分析脚本和作图脚本可以直接读取它们，重新得到报告中的数字和图。
- **`notes/` 是实验过程的记录，不是结论。** 其中保留了被推翻的假设和中途的估计。与报告不一致时，以报告为准，更正经过见报告附录 C。

`tools/` 另有几个各章共用的目录：

- `common/`：运行器与采样器，例如 `bondrun.m`、`anecc.m`、`smcpower.c`、`pclus.c`；
- `lib/`：编译产物的解析库；
- `re/`：只读的逆向工具；
- `figs/`：报告用图的生成脚本。图的配色采用 ggsci 的 NPG 配色。`build_all.sh` 一次重新生成全部图：各脚本先出中文浅色版，`translate.py` 按 `i18n/` 中的对照表生成英文版，`darken.py` 生成深色版，`render.sh` 把 SVG 导出为 PNG；
- `site/`：`build.py` 把报告生成单页网页（`--lang zh` 输出到 `site/`，`--lang en` 输出到 `site/en/`）；
- `check_en.py`：逐节比对英文译本与中文原文（数字、交叉引用、文献引用、证据标注、表格和图）。

报告附录 A 按章列出每个实验所用的工具、数据和是否需要 root，附录 B 是数据目录。

## 不在本仓库中的内容

- **ANE 固件、kernelcache、编译器的反汇编和硬件参数表的原始导出。** 它们是 Apple 二进制文件的派生物，只在本地做只读分析，不分发。报告给出了重新生成这些内容的工具，读者可以在自己的机器上运行。
- **第 14 章实际应用测试的大部分原始记录。** 目前只有 ANE 资源曲线整理入库（`data/12_apps/`），其余见报告附录 B.3。

## 复现

基本条件：

- **硬件与系统**：大部分实验需要 M6。Core ML 算子分派、零激活功耗对照和编译器调试器观测在 M4 上进行。系统为 macOS 27.0.1（26A434）；其他版本的系统自带的 ANE 编译器不同，结果可能有差异。
- **软件**：
  - Xcode 命令行工具（`clang`）；
  - 生成模型需要装有 coremltools 9.0 与 PyTorch 2.7 的 Python 环境；
  - 分析脚本只需 numpy，作图另需 scipy 与 matplotlib。

步骤：

1. **准备工作目录。** 把所需的工具与生成脚本复制到同一个工作目录。脚本按 `./bondrun` 这样的相对路径互相调用，假定工具平铺在同一个目录中。`tools/deploy_m6.sh` 可以把整个 `tools/` 平铺同步到另一台机器，用法见脚本开头。
2. **编译工具。** C 和 Objective-C 工具的编译命令写在各文件开头，例如：
   ```bash
   clang -fobjc-arc -O2 bondrun.m -framework Foundation -framework CoreML -o bondrun
   ```
3. **生成模型并运行实验。** 需要 root 的只有 kdebug 采集脚本（`*_ktrace.sh`、`d1_trace.sh`、`gov_step.sh`、`gov_target*.sh`），以 `sudo` 运行。脚本内部以普通用户身份运行负载，结束后把结果文件的属主改回普通用户。
4. **重跑分析。** 分析脚本读取 `data/` 中的原始数据，在任何一台 Mac 上都可以重跑，不需要 M6。报告中的图由 `tools/figs/` 的脚本从同一份数据生成。

报告附录 A.3 给出了三个从生成模型到得出结论的完整示例。研究遵守的约束及其例外见报告第 1.4 节和第 3.2 节，主要有：只通过公开接口执行、观测只读、不分发固件与反汇编、不修改系统安全设置。
